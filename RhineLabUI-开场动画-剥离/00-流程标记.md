## 五、标记怎么读 / 怎么验

**标记词**：`// ▶ 阶段N 名称 · 时间段 · 原片帧号`

标记全部加在**行尾**，不插入新行。所以：

- `标记/boot.ts` 第 138 行 = `源码/src/boot.ts` 第 138 行；
- 把 `标记/` 每个文件里的 `// ▶ …` 后缀全部剪掉，得到的就是上游原文件（逐字节相同）。

**复现与自检**：

```bash
cd /home/xuan/设计/RhineLabUI-开场动画-剥离
python3 剥离.py
```

脚本会自己查三件事，任何一件不通过就退出码 2 并列出问题行：

1. 每个锚点必须命中（找不到就报错，不静默跳过）；
2. `源码/src/` 每个文件逐字节等于上游；
3. `标记/` 每行剪掉标记后逐字节等于上游，且行数不变。

当前结果：**114 处标记，三项自检全部通过**。

## 六、这套代码真正值得抄的地方

1. **三层分离**：时间轴（纯计算 `boot-motion.ts`）→ 曲线表（`boot-*-tracks.ts`）→ 写入器（`boot.ts`）。因此拖动进度条、倒放、跳帧、减少动效降级全是白拿的。这比它的视觉更值得抄。
2. **音画同源**：`boot.ts` 与 `audio.ts` 读同一个 `t`，不是音频去追动画。
3. **纯函数时间轴**：`bootMotion(t)` 无状态，同一帧永远同一画面。
4. **离散切帧用帧号、连续位移用秒**：前者按原片帧号对齐，后者走插值曲线。
5. **插值用单调三次 Hermite**：逐段缓动会在每个关键帧停顿，这条曲线全程速度连续。

## 七、已知限制

- 仓库 `verification/BOOT-MOTION.md` 自己写明：轨迹是**逐帧目测 + 测量脚本拟合**，作者明确不声称拿到原视频工程里的原始动画曲线。所以 `boot-tracks.ts` 这些数值**长得像真数据但不是真数据**，抄的时候心里有数。
- 我没有把上游项目跑起来（要 `npm ci` + 模型资源），所以「代码怎么写」我能保证，「跑起来什么手感」我不能保证。
- 上游 `src/boot-lettering-art.json` 是单行 29 KB 的 JSON，不能加注释，标记版里它没有行尾标记 —— 它的阶段归属（3 auth / 5 welcome）在本文第三节。
- 片段是从超大文件里按行段抽的，行号是原文件行号，不是片段内的行号。
