## 2. 浏览器实测（真实加载与播放）

```bash
python3 -B verification/browser-check.py --baseline /tmp/xi-opening-before-1rkg11tC
```

### 2.1 加载期阻塞与帧间隔

| 页面 | 最长帧间隔 | 加载期长任务 | 位置采样数 | 7.2 秒后残留循环 |
|---|---:|---:|---:|---|
| 改动前 头像（两次运行） | 200.1 / 133.3 ms | 61 ms、153 ms / 136 ms | 28 | 有（`sample` + `loop`） |
| 改动后 头像（两次运行） | 66.7 / 33.4 ms | **无** | **64** | **无** |
| 改动后 欢迎→扫描环 | 16.8 ms | 无 | — | 无 |

- 帧间隔中位数三者都是 16.7 ms（等于 60 Hz 的垂直同步周期），说明改动前后稳态都满帧。
- 平均每帧 JS 回调总耗时可忽略：改动前 49.0–54.8 ms / 7 秒，改动后 52.5–55.2 ms / 7 秒。**这一项没有改善，也不该被说成改善** —— 优化点不在稳态开销，而在加载期阻塞、位移采样密度和残留循环。
- 位置采样从 28 个变成 64 个：改动前 4.8 秒里头像只被摆到 28 个不同位置（每秒约 25 帧的台阶），改动后按显示刷新连续摆放。这是「顺一点」的实际来源。
- 加载期长任务消失：头像的逐像素处理搬到构建期，浏览器只剩解码与合成。

### 2.2 退格删除的时序（本轮修的问题）

改动前：一个字先淡出 3 帧，停住，光标再用 7 帧滑过去 —— 两件事被拆成两个动作，读起来是「字先没了，光标才追过去」。

改动后：光标横跨字形与字形淡出共用同一个进度值，光标落到新边界的那一帧，字形刚好归零；之后停 3 帧作为下一字的拍子。总时长不变（仍是 4.80 秒）。实测轨迹（`XI`，框内是字符盒）：

| 帧 | 光标 x | `X` 透明度 | `I` 透明度 |
|---:|---:|---:|---:|
| 96 | 1126.0 | 1 | 1 |
| 99 | 1110.0 | 1 | 0.606 |
| 100 | 1102.0 | 1 | 0.394 |
| 103 | 1086.0 | 1 | **0** |
| 110 | 1027.0 | 0.394 | 0 |
| 113 | 989.0 | **0** | 0 |

`I` 的字符盒是 [1086.0, 1125.8]，`X` 的是 [988.8, 1086.0]。断言：

- 字形归零那一帧，光标与新边界的误差 ≤ 0.51px（实测 1086 vs 1086、989 vs 988.8）——**没有「字没了光标还在滑」的空窗**。
- 透明度最接近 0.5 的那一帧，光标严格落在该字形内部（实测帧 100 与帧 110），即光标是扫过**还看得见**的字，不是扫过空白。
- 归零之前每一帧透明度都 > 0（不存在先隐形再滑）。
- 光标位移全程单调不减（不会来回抖）。

截图：`screenshots/删除中-f99-放大-裁切.png`（光标压在半个 `I` 上的放大图）、`删除中-f110.png`。

## 4. 没验的部分

- 真实显卡下的呈现帧率。本机为软件光栅，不能代表有 GPU 的机器。
- 真机触屏的手势与倾斜关闭行为（仅用媒体特性模拟了触屏指针类型）。
- Safari、Firefox。倾斜依赖 3D 变换与 `perspective`，本次只在 Chromium 上验过。
- 长时间（分钟级）驻留与内存增长。
- 拼接页段间交叠 120 ms 的观感是否合适 —— 需要你自己看一眼再定。

## 5. 三段拆分包（`发包/`，2026-10-25 实测）

`打包.py` 把开场拆成三个单文件页面，CSS、脚本、字体、头像全部内联成 data URI。
用无头 Chromium 以 `file://` 打开，各播一遍至结束：

| 页面 | 声明时长 | 实测结束 | 绘制次数 | 外部请求 | 未捕获异常 |
|---|---:|---|---:|---|---:|
| 01-头像段 | 4.800 s | `ended: true` | 292 | 只有自身文档 + 4 条 `data:` | 0 |
| 02-欢迎页 | 3.400 s | `ended: true` | 207 | 只有自身文档 + 1 条 `data:` | 0 |
| 03-扫描环 | 3.275 s | `ended: true` | 198 | 只有自身文档 + 1 条 `data:` | 0 |

- 阶段标记核对：欢迎包全程 `stage.dataset.boot === 'welcome'`，扫描环包全程 `'scan'`；两包都不会闪到另一幕。
- 生成物 SHA-256 前 12 位：头像 `3ee1c4c9ce1b`、欢迎 `7042d9f5f583`、扫描 `96c51678ac74`；连续跑两次打包，三个哈希一致。
- 单文件体积：头像 201,557 B、欢迎 114,582 B、扫描 114,582 B；zip 分别为 143,247 / 59,138 / 59,144 B。
- 三个包都带同一版 `shared/tilt.js`：欢迎包会跟随鼠标，扫描环包不跟随（与整条片一致）。
- `node verification/logic-check.cjs` 与 `python3 -B verification/browser-check.py --quick` 在本轮改动后仍通过，
  `拼接.html` 整条播放到结束、两个子页面待执行回调归零。
- 新增源码参数：`?stage=welcome|scan` 只播一幕；打包页面把它写死为 `window.__XI_STAGE__`，因此 `file://` 下无需查询串。
