### 两版的差异只有两个颜色

`build.py` 里只有一个工厂函数 `palette()`，两版共用同一套时间轴、故障引擎、alpha 映射，
**唯一差别是墨色与发夹色**：

```python
COLOR = palette(TEAL,     CLIP_RED, "color", ...)   # 暗青绿 (84,172,154) + 暗红 (178,36,48)
MONO  = palette(WHITE,    CLIP_RED, "mono",  ...)   # 纯白 + 仍然是暗红
```

黑白版的发夹**必须还是红的**（用户要求）：红是画面里唯一的色相锚点，去色后整个画面
只剩黑白灰，发夹会跟着丢。所以两版的 `CLIP_RED` 是同一个值。

> 暗青绿 `(84,172,154)` 不是拍脑袋挑的，是按参考产物的实测值反推的：
> 参考图人像内容像素 P10 RGB(30,63,56) / P50 RGB(47,96,86) / P90 RGB(63,129,114)，
> 三通道比约 47:96:86，取 G=172 归一化 → `(84,172,154)`。
> 这样参考图的 P50 对应到本模板的 alpha≈0.56，与发块的取值区间正好对齐。

四个必须过的检查（脚本是一次性的，结论记在下面，改完重跑）：

| 检查 | 判据 |
|---|---|
| **帧率** | 用 CDP 读 `window.__stats = {frames, drops, fps, worst}`。要求 60.0 FPS、掉帧 0 |
| **配色约束** | 逐像素验墨色通道比 = 参考值；黑白版除发夹外不许有杂色像素 |
| **故障可见性** | 扫帧找故障窗，**取窗内最大值判定**（只采窗内第一帧会误报）。故障窗外相邻帧逐像素最大差必须为 0 |
| **面部留白** | 按掩膜真实形状采样，脸内绿通道均值应 ≈0 |

> ⚠️ 必须用完整 `chrome`，不能用 `chromium_headless_shell`；
> `--virtual-time-budget` 对 rAF 无效，冻帧只能靠 `?f=` 参数。
> ⚠️ 无头视口实际是 1920×937（浏览器 chrome 占位），不是 1080。

## 四、当前时间轴（25 FPS，帧号索引）

```
f0-2      纯黑上电
f3-25     头像「居中」区块拼装   12 列 × 16 行 = 192 格（at = 3 + REV_POS[ci] * 0.40）
f26-27    拼装完成
f28-40    锁定期爆发：区块闪烁，密度从高衰减到 0
f40-66    头像左滑 26 帧，位移 23% 舞台宽（屏心 50% → 版位 26.5%）
f54-76    WENSI 滑入 22 帧
f56-78    AUTOMATION 滑入 22 帧（比 WENSI 错开 2 帧）
f84+      稳态：每 70 帧（2.8s ±25% 抖动）来一次 11 帧（0.44s）区块闪烁
          其余时间画面完全干净
```

整段入场约 **3.1 秒**（不含无限循环的稳态故障）。

### 动效曲线（取自 RhineLabUI，不是自己拟的）

| 用途 | 来源 | 特征 |
|---|---|---|
| 插值 | `boot-tracks.ts` 的 `track()` | **单调三次 Hermite**。逐段缓动会在每个关键帧停顿，这条曲线全程速度连续 |
| 头像左滑 | 原片 logo 的 `leftEdge`（34 帧曲线，归一化成 `SLIDE_KEYS`） | 慢起 → 中段最快 → 长尾减速 |
| 文字滑入 | **同一条 `SLIDE_KEYS`**，压到 22 帧里播 | 均匀加减速，无起步冲击 |
| 墨比位移先到 | `INK_OPACITY` | 透明度只在前 3 帧就 0→1，此时位移还在走 |
| 两行错开 | 原片 brand 三行错开 2 帧的做法 | WENSI 与 AUTOMATION 错开 2 帧 |

> **踩过的坑**：一开始用原片的 `brandX`（234→0）做文字滑入，但它**前 4 帧就走完 51%**，
> 读起来是「跳」不是「滑」。用户反馈「要更平滑」后换成 `SLIDE_KEYS`。

### 故障：只有「区块闪烁」一种形态

用户明确要求：**保留区块闪烁，不要整个头像闪**。
所以切片撕裂、色差、滚动、色阶断层、反相、扫描线噪点、区块重排**已全部删除**，
连它们的预渲染变体也一并删掉（模板从 27 679 B 降到现在的体积）。

现在的实现只有一个函数：

```js
blockFlicker(f, hold, pHaze, pHole)
// 每块按 hash 决定这一拍是否参与；参与的块先 clearRect 挖空，
// 其中一部分再画回 V.ghost（青雾，未解析感），其余留空 → 黑洞
```

- 单块状态每 `hold=3` 帧变一次；相位按 `Math.floor(step/3)` 错开，不让所有块共享同一个边界
- 全部随机性来自 `hash(ci * 977 + s * 7919)` 这类整数哈希——**全程禁用 `Math.random`**，
  所以任何一帧都可以复现
- **方块以外的像素逐帧不动**（硬要求，已实测：故障窗外相邻帧逐像素最大差 = 0）

## 五、几个必须交代的设计决策

### 1. 面部是一块「负形」，不是色块

参考图里头像的脸里**什么都没有**，是一块纯黑的空白，只有一条细青线勾出
额头→鼻→唇→下巴的轮廓。所以做法是**把脸挖空**（alpha 置 0，直接露黑底），
而不是往脸里填色。

> **踩过的坑（最贵的一个）**：最初把「留白」理解成「平涂一块颜色」，
> 往脸里填了一层 `vFace = 0.74`。方向完全错了，绕了很多圈才纠回来。
> **用户说「留白」= 纯黑负形，不是「填一块色」。**

轮廓线**不需要自己画**——它来自源图自身的暗边。曾经自造过一个「轮廓环」
（把掩膜向外膨胀 2px），结果它跟着掩膜的人造直边和内部空洞一起补出假线
（下颌一条直角、耳朵一圈环），已删除。

### 2. 面部掩膜是「泛洪 + 连通块」选出来的

`facemask.png` 不是直接光栅化 SVG 里那个 `<mask id="face-m">`——那个 mask 用的是
深色填充（= 遮住的部分），方向是反的，光栅化出来是一块带洞的怪形状。

真正的做法（`threshold 242 → 四边泛洪 → 取「最右伸出最远且面积 >1 万」的连通块`）：

1. 亮度 ≥ 242 标为「亮」（源图背景 255、脸 229~255、头发 204~229，**分界线在 229~232**）
2. 从四边泛洪穿亮像素，能到的是**外部背景**
3. 剩下的亮区就是被发丝围合的部分——但这里面既有脸，也有头发里的一块浅色带
4. 按「最右伸出最远」挑连通块 —— 侧脸的轮廓必然顶到最右，浅色带不会

实测结果：面积 72 551 px，bbox x816~1108 y430~857（1254 空间），正是刘海下→眼鼻颊→下巴→下颌。

> **两个坑**：
> - 阈值曾写成 248.5，而脸只有约一半像素达标 → 半个脸被当头发
> - 挑连通块时先按「面积最大」选，选中的是头发里那块浅色带（101 595 px），不是脸

### 3. 头发是离散色阶，不是连续渐变

参考图的头发不是一条渐变，而是几个离散色阶（浅色高光带 + 中调 + 暗块），
实测落在绿 50/70/90/110/130 附近。所以把 detail 量化到 6 档：

```js
const v = 0.20 + 0.56 * (Math.round(detail * 5) / 5);
// → 绿 34 / 53 / 73 / 92 / 111 / 131，顶档就是「浅色」
```

源图亮度映射是**反相**的：暗的发块 → 亮的墨色。`detail = ((255-lum)/118)^0.78`。

**亮度上限 232** 是必须的：脸和背景在前面已经挖掉了，剩下的像素里亮度 >232
只可能是「发块里的一块浅色填涂」，按反相映射它会掉到最暗一档，在头发里看就是个洞。
截在 232 → detail 0.279 → 量化到第 1 档 → 绿 53.7，正好和周围发块同色号。

### 4. 挖空只能由 `FACEM` 决定

> **踩过的坑**：挖空条件一度写成 `FACEM[p] || white[p]`（`white` = 亮度 ≥248.5）。
> 头发里本来就有浅色填涂，于是被一并挖空，发块上凭空多了 7 处黑洞
> （最大一块 19 774 px）。`white` 现在只用来跑泛洪标外部背景，不参与挖空。

### 5. 扫描线是头像质感的一部分，不是背景装饰

参考产物里头像内部有 3px 周期的横向扫描线，逐相位相对亮度 `[1.058, 1.057, 0.885]`，
峰谷差 17.4%。这条**保留**（属于头像质感）。

但**背景**上不许有任何扫描线、网格、渐变、暗角——用户明确禁止过。

### 6. 位移用 `calc(var(--stage) * n)` 而不是 JS 测像素

```css
--stage: min(100vw, 177.78vh);   /* 锁 16:9，居中的舞台宽度 */
```

所有位移都写成 `calc(var(--stage) * n)`，窗口缩放时自动跟着变，不用 JS 测量、
不会有一帧的滞后。

### 7. 画布分辨率必须按显示尺寸取

曾经画布是 774px 位图铺在 773.6 CSS px 上（1.00 比例，勉强还行），但如果写死
尺寸就会在别的窗口下糊掉。现在按实际显示尺寸算：

```js
const cssW = stageW * 0.4644;      // 人像占舞台宽 46.44%，同 .portrait-wrap
```

## 八、已知限制与悬留项

1. **上手即全自动播放**，没有播放入口，也不响应空格/方向键。
   暂停/重播只能靠代码或改 `?f=`。要不要加控制条，用户没要求，未做。
2. **`reset()` 绑在「点击整个舞台」上**，不是显式按钮——所以鼠标点画面任意处
   都会从头再放一遍。这是删掉 `[ REPLAY ]` 按钮后的折中。
3. **黑白版亮度口径**：当前墨色是纯白 `(255,255,255)`，所以整体亮度高于彩色版。
   如果哪天要「与彩色版观感亮度一致」，把 `MONO` 的墨色换成灰 `(152,152,152)` 即可，
   一行改动。
4. **稳态故障是无限循环的**（每 2.8s 一次）。如果这是要当片头用（放完就切走），
   把 `G_START` 之后的分支去掉即可停在 f84。
5. **字体只内联了拉丁子集** `CalSans-latin.woff2`。当前两行文字都是拉丁字母，
   够用；如果以后加中文字，会掉到 fallback 字体。
6. **没有响应式竖屏版**。舞台锁 16:9，窄屏上下留黑。竖屏手机看会偏小，
   但版式不会散（所有位移都是 `--stage` 的比例）。
