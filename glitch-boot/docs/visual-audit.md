## 3. 两版对比：MONO 更好

同一像素掩膜（用 MONO 稳态帧的头像区域取掩膜）实测：

| 指标 | MONO | DUOTONE |
|---|---|---|
| 头像区平均亮度 | **105.9** | 77.6（暗 27%） |
| 头像区亮度标准差 | **34.9** | 23.4（平 33%） |
| 面部 vs 发块亮度差 | **76.2** | 52.1（少 32%） |
| 彩色像素占比 | 0 | 14.3% |

同一故障帧的变化量（与各自静止帧比、差异>10 的像素占比）：

| 帧（周期档） | MONO | DUOTONE |
|---|---|---|
| f165（①切片撕裂 t=0） | **1.60%** | 1.42% |
| f337（③垂直滚动 t=0） | **2.73%** | 2.62% |
| f251（②色差撕裂 t=0） | **12.39%** | 8.00%（但红像素占头像区 2.31%，基线 0.42%） |

结论：

1. **MONO 赢在头像**：白墨的亮度承载了发块的晕染层次，脸/发分离清楚；DUO 的绿墨 (34,242,122) 亮度只有 189（白=255），同级 alpha 下整体暗 26%，脸和发块挤在同一个色相里，1:1 看头就是一个绿团（只有红发夹在那儿扎眼）。
2. **MONO 赢在系统**：全片只有"黑底 + 白墨 + 黑底白字/白底黑字"一套语言，和 WENSI／AUTOMATION 的字形块是一体的；DUO 是绿色插画 + 红发夹 + 红中分线 + 红角标 + 黑白字块，三套东西在抢。
3. **DUOTONE 唯一赢的一项**：②色差撕裂。MONO 里 cA/cB 两份副本都是白墨（`ad[i]=255,255,255`、`bd×0.30`），叠出来是"白色重影／双重曝光"，读作"画面糊了"；DUO 里是红/绿分离 + 左侧红边，才是真正的色差故障。
4. 其它五档（①②③④⑤⑥ 里除 ② 外）本质是明度变换，DUO 只是把它们整体压暗 → 全部比 MONO 弱。

**所以：默认用 MONO，把 MONO 的 ② 从"白色重影"改成明度分离**（两份副本里一份取 `V.inv` 或 `V.step`，让错位以一亮一暗的形式出现），就能把 DUO 唯一的优势补回来，同时不动整体调性。若一定要留 DUO，见建议 9。

## 4. 可执行建议（按优先级）

**P0（低成本、收益大）**

1. **括号对比度**：`--line:#2b2b2b`(L43) × opacity .5 = 实际 L17，在黑底等于不存在。要么把 `.brk` 的线色改成 `--accent`、opacity 提到 1；要么直接删掉这 4 个节点和 f62-74 这段动画，别留一个"看着像 bug 的暗角"。验证：f330 截图里 brk-tl 区域最亮值 ≥ 120。
2. **f8-f34 太暗 / 拼装看不出**：三选一 ——（a）把底影 `V.ghost` 的 alpha 提到 ~22%（现在约 11%）；（b）把拼装窗口 `REV_POS[ci]*0.78` 收到 `*0.5`（结束帧 43 → 30），留出时间给爆发；（c）网格从 6×8=48 加密到 8×11=88，格子小一半，"解析"感更强。验证：f8 头像区亮过 40 的面积应从 7.95% 提到 ≥20%。
3. **f57 过曝**：色阶断层/反相那一档要把均值保住 —— 量化后按 `q` 分布做一次亮度归一，或把该档包络 env 上限压到 0.6。验证：故障帧头像区均值偏离稳态 ≤ ±15%（现在 +70%）。
4. **最后 1.4 秒静止**：总长从 175 收到 ~150 帧（6s），或把 REPLAY/状态条的落位提前，让收尾有个"落定"的动作。验证：f140→f160 的变化量从 0.19% 提到 ≥2%。

**P1**

5. **面部硬边（根因）**：`white[p] = (lum >= 248.5)` 这个二值判断是锯齿来源。改成软掩膜 `const w = clamp01((lum - 232) / 23)`，再 `v = (0.13+0.87*detail)*(1-w) + (0.62+0.38*detail)*w`。一次修掉锯齿和面部/发块的生硬接缝。（更彻底：SVG 里已有 `face` 组，直接在 891px 目标分辨率上光栅化该组当遮罩，连泛洪都不需要。）
6. **画布分辨率**：显示画布按 `width = height = Math.round(pwrap.clientWidth * devicePixelRatio)` 建，把 720 的合成结果一次平滑放大；或把 `.portrait-wrap` 宽度从 86% 降到 69.4%（=720/1036.8）做到 1:1 不缩放。验证：`getComputedStyle(#glitch).width` 与 `#glitch.width` 相等。
7. **状态条 CJK**：`ID 温曦` 提到 ≥12px（或删掉），`Share Tech Mono` 后面显式接一个中文族；状态条上边框从 #2b2b2b 提到 ~35% 亮度。验证：1:1 截图能读清"温曦"。
8. **①切片撕裂的过亮扫描线**：`fillRect(0, b.y, SZ, 2)` 当 band 落在 y=0 时，横线正好压住画布顶边，容易被读成"渲染 bug"（拼图 t18 那条线就是这个位置）。把 y0 的取值从 `hash*SZ*0.8` 改成避开首尾各 5% 的带。

**P2**

9. **若保留 DUO**：给绿墨做亮度补偿（189/255 = 0.74，则 `d[i+3] = round(255*v/0.74)`），或换成更亮的绿（如 #A6FF6E，亮度≈224）；红只留在"错"的地方（发夹 + 中分线），别让角标也红，否则红色失去焦点。
10. **REPLAY**：1px 亮边，或让它在 f150 就出现（别等到 f160，那时画面已经静止了）。
