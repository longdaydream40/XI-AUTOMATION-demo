### 第二段：第一行（AURORA）的光标 + 退格删除

> 第一行的文案在第 32 次构建时从 `WENSI` 改成 `AURORA`（用户要求，只改这一个）。
> 模板里的 id 与变量名仍是 `w-wensi` / `wWensi`，没跟着改名，见 §八.10。

```
f84        AURORA 最右端出现光标（周期 12 帧，亮 8 暗 4）
f96        开始退格删除，每字 8 帧：字淡出 3 帧 → 光标滑到新边界 5 帧
f144       6 个字符删完（整 48 帧 = 1.92s），光标停在行首继续闪
```

**每字帧数由「总长上限 ÷ 字数」推出来，不是写死的**：`DEL_TOTAL = 50`（2.00s）、
`DEL_STEP = floor(50 / 字数)`。所以 5 字时是 10 帧/字（正好 50 帧），
现在 6 字是 8 帧/字（48 帧 = 1.92s），都落在「2 秒内」这条要求里。
以后再改文案长短，不用手动重算帧数。

三个设计点值得记一笔：

- **删除不用裁切，改成逐字淡出。** 原因见 §五.8：裁切会把当前这个字切成两半，
  光标左边永远挂着一条被切开的残片；窄字（如 `I`）被切开就是一根竖线，
  看上去像光标拖着一条尾巴。现在每个字符是独立的 `<span class="ch">`，
  删到谁谁淡出，全程不裁文字。
- **下刀位置按真实字宽定位**，不是按字号均分。AURORA 里 `A` 81.7px、`O` 97.1px，
  均分会让光标停在字中间。实现用 `Range` 逐字量右边界，
  存成与字号无关的比例（窗口缩放不用重量）。
- **光标落在屏幕整像素上**，见 §五.8。

用户明确要求：**保留区块闪烁，不要整个头像闪**。
所以切片撕裂、色差、滚动、色阶断层、反相、扫描线噪点、区块重排**已全部删除**，
连它们的预渲染变体也一并删掉（模板从 27 679 B 降到现在的体积）。

现在的实现只有一个函数：

```js
blockFlicker(f, hold, pHaze, pHole)
// 每块按 hash 决定这一拍是否参与；参与的块先 clearRect 挖空，
// 其中一部分再画回 V.ghost（青雾，未解析感），其余留空 → 黑洞
```

## 五、几个必须交代的设计决策

### 1. 面部是一块「负形」，不是色块

参考图里头像的脸里**什么都没有**，是一块纯黑的空白，只有一条细青线勾出
额头→鼻→唇→下巴的轮廓。所以做法是**把脸挖空**（alpha 置 0，直接露黑底），
而不是往脸里填色。

> **踩过的坑（最贵的一个）**：最初把「留白」理解成「平涂一块颜色」，
> 往脸里填了一层 `vFace = 0.74`。方向完全错了，绕了很多圈才纠回来。
> **用户说「留白」= 纯黑负形，不是「填一块色」。**

轮廓线**不需要自己画**——它来自源图自身的暗边。曾经自造过一个「轮廓环」
（把掩膜向外膨胀 2px），结果它跟着掩膜的人造直边和内部空洞一起补出假线
（下颌一条直角、耳朵一圈环），已删除。

### 2. 面部掩膜是「泛洪 + 连通块」选出来的

`facemask.png` 不是直接光栅化 SVG 里那个 `<mask id="face-m">`——那个 mask 用的是
深色填充（= 遮住的部分），方向是反的，光栅化出来是一块带洞的怪形状。

真正的做法（`threshold 242 → 四边泛洪 → 取「最右伸出最远且面积 >1 万」的连通块`）：

1. 亮度 ≥ 242 标为「亮」（源图背景 255、脸 229~255、头发 204~229，**分界线在 229~232**）
2. 从四边泛洪穿亮像素，能到的是**外部背景**
3. 剩下的亮区就是被发丝围合的部分——但这里面既有脸，也有头发里的一块浅色带
4. 按「最右伸出最远」挑连通块 —— 侧脸的轮廓必然顶到最右，浅色带不会

实测结果：面积 72 551 px，bbox x816~1108 y430~857（1254 空间），正是刘海下→眼鼻颊→下巴→下颌。

> **两个坑**：
> - 阈值曾写成 248.5，而脸只有约一半像素达标 → 半个脸被当头发
> - 挑连通块时先按「面积最大」选，选中的是头发里那块浅色带（101 595 px），不是脸

### 3. 头发是离散色阶，不是连续渐变

参考图的头发不是一条渐变，而是几个离散色阶（浅色高光带 + 中调 + 暗块），
实测落在绿 50/70/90/110/130 附近。所以把 detail 量化到 6 档：

```js
const v = 0.20 + 0.56 * (Math.round(detail * 5) / 5);
// → 绿 34 / 53 / 73 / 92 / 111 / 131，顶档就是「浅色」
```

源图亮度映射是**反相**的：暗的发块 → 亮的墨色。`detail = ((255-lum)/118)^0.78`。

**亮度上限 232** 是必须的：脸和背景在前面已经挖掉了，剩下的像素里亮度 >232
只可能是「发块里的一块浅色填涂」，按反相映射它会掉到最暗一档，在头发里看就是个洞。
截在 232 → detail 0.279 → 量化到第 1 档 → 绿 53.7，正好和周围发块同色号。

### 4. 挖空只能由 `FACEM` 决定

> **踩过的坑**：挖空条件一度写成 `FACEM[p] || white[p]`（`white` = 亮度 ≥248.5）。
> 头发里本来就有浅色填涂，于是被一并挖空，发块上凭空多了 7 处黑洞
> （最大一块 19 774 px）。`white` 现在只用来跑泛洪标外部背景，不参与挖空。

### 5. 扫描线是头像质感的一部分，不是背景装饰

参考产物里头像内部有 3px 周期的横向扫描线，逐相位相对亮度 `[1.058, 1.057, 0.885]`，
峰谷差 17.4%。这条**保留**（属于头像质感）。

但**背景**上不许有任何扫描线、网格、渐变、暗角——用户明确禁止过。

### 6. 位移用 `calc(var(--stage) * n)` 而不是 JS 测像素

```css
--stage: min(100vw, 177.78vh);   /* 锁 16:9，居中的舞台宽度 */
```

所有位移都写成 `calc(var(--stage) * n)`，窗口缩放时自动跟着变，不用 JS 测量、
不会有一帧的滞后。

### 7. 画布分辨率必须按显示尺寸取

曾经画布是 774px 位图铺在 773.6 CSS px 上（1.00 比例，勉强还行），但如果写死
尺寸就会在别的窗口下糊掉。现在按实际显示尺寸算：

```js
const cssW = stageW * 0.4644;      // 人像占舞台宽 46.44%，同 .portrait-wrap
```

### 8. 第二段的删除不用裁切，光标必须落在整像素上

这条是把用户反馈「光标移动会留下竖线」查到底之后定下的。

**根因一：裁切会把字切成两半。** 第一版用 `clip-path: inset(0 N% 0 0)` 做了
一道从右往左扫的裁切边，光标贴着裁切边停。看着是「逐字擦除」，实际是：
光标扫过某个字时，这个字左边没被裁掉的那一截留在光标左侧——
`I` 只剩 3.5px 宽的竖条、`I` 本来就是一根竖线，于是读起来就是
「光标拖着一根竖线」。实测 f100 的像素图：`I` 残留 1342–1345 与
光标 1345.55–1354.84 连成一片 13px 宽的白块。

**根因二：分数像素的光标，两边会被抗锯齿涂成半透明。**
盒子本身就在小数位置（文字盒 x=984.97），光在盒子内部取整救不了它 ——
取整必须对着**屏幕绝对坐标**做。所以 `snapCaret()` 同时把光标的
`left / top / width / height` 四舍五入到整数像素，见 `measureChars()`。

两项都修完之后实测：光标自身矩形内 100% 满墨，两侧相邻列全黑（输给字形的除外）。

## 八、已知限制与悬留项

1. **上手即全自动播放**，没有播放入口，也不响应空格/方向键。
   暂停/重播只能靠代码或改 `?f=`。要不要加控制条，用户没要求，未做。
2. **`reset()` 绑在「点击整个舞台」上**，不是显式按钮——所以鼠标点画面任意处
   都会从头再放一遍。这是删掉 `[ REPLAY ]` 按钮后的折中。
3. **亮度口径**：墨色是纯白 `(255,255,255)`，所以对比度拉得很满。
   如果哪天要压暗（例如靠近旧彩色版暗青绿 `(84,172,154)` 的观感亮度），
   把 `MONO` 的墨色换成灰 `(152,152,152)` 即可，一行改动。
4. **故障只出现在 f28–40，之后不会再有。** 现在 `runGlitch()` 里就一条分支：
   `if (f < 28 || f > 40) return;`。哪天想把「稳态偶发闪烁」加回来，在这里补一条
   `f > G_START` 的分支即可（旧实现见 git 历史 / `docs/` 里的审计报告）。
5. **字体只内联了拉丁子集** `CalSans-latin.woff2`。当前两行文字都是拉丁字母，
   够用；如果以后加中文字，会掉到 fallback 字体。
6. **没有响应式竖屏版**。舞台锁 16:9，窄屏上下留黑。竖屏手机看会偏小，
   且**第 32 次换文案后手机竖屏会出界**：390×844 实测 AURORA 右边缘 409.5 px、
   舞台右边缘 390 px，末位字母会被 `overflow:hidden` 切掉 19.5 px（旧的 WENSI
   有 22.7 px 富余，所以这是换字带来的）。一行 CSS 能盖住：给 `#w-wensi` 的
   `font-size` 再加两个上限 `min(clamp(54px,9.6vw,124px), 12.4vw, 22vh)` ——
   12.4vw 是「0.48 × 舞台宽 ÷ 3.865em（AURORA 实测字宽）」推的；
   1920×1080（124px）与 720×1280（69.1px）都不会被这两个上限碰到，
   只有极窄屏才生效。用户没要求，未动。
7. **第二段的删除节奏是「先淡出、后滑动」，不是同步。** 一个字 8 帧：
   0–2 帧字淡出、2–7 帧光标滑到新边界，中间不留停顿（帧数随字数变，见 §四）。
   想要更「实时」的手感（字在光标滑过时消失）或更慢的节奏，改 `DEL_TOTAL` /
   `DEL_FADE` 两个常量即可。
8. **删完之后光标永久保持闪烁**，`AURORA` 不会再打回来（用户没要求恢复）。
   要停在「删完就不再闪」，把 `render()` 里那段 `CUR_BLINK` 判断去掉即可。
9. **「好不好看」得你自己看。** 数据层已经量到底了：
   DOM 时间轴（f84 出现 → f96–144 每字 8 帧 → 第一行盒宽恒 479px）、
   画面级逐帧量（见 §六）、像素锐利度（光标自身矩形 100% 满墨）。
   剩下两件事只有你能定：第一次删除前那段光标闪烁（0.48s）够不够长，
   以及整体删除速度是不是你要的「流畅」。
10. **模板里的内部命名没跟着文案改。** id 还是 `w-wensi`、变量还是 `wWensi`，
    CSS 选择器 `#w-wensi` 也是。改它要动 3 处选择器和 7 处 JS 引用，
    对画面零影响，所以没动 —— 看代码时把 `wWensi` 读成「第一行」就行。
11. **页签标题与模板顶部那行身份注释还是 `WENSI AUTOMATION`**（前者在 `build.py` 的
    `TITLE`，进 `<title>`；后者是 `engine.template.html` 第一段注释）。动画里看不到它们，
    用户只说改屏幕上的那一行，所以没动。要改：`MONO = palette(..., "AURORA AUTOMATION · MONO", ...)`
    加模板顶部那行注释。另外 JS 里还留着一句引用用户原话的注释（「WENSI / AUTOMATION
    完整显示之后头像不许再闪」），那是需求原话，故意不改。

### `拼接.html`：两条演示线首尾接起来

`index-bw.html`（A，5.84 s，切点 = 第 146 帧，退格删除刚好收尾）硬切到 `WENSI-开场动画`（B，6.68 s，停在扫描环末帧）。
两段各跑在自己的 iframe 里 —— A 是 canvas + 25 FPS 共享时间轴，B 是 DOM + `bootMotion` 纯函数，
塞进同一个 document 只会互相踩 body / style / rAF。B 到点才开始建（不提前起跑），A 从 DOM 摘掉以停掉它自己的 rAF。
参数：`?order=ba` 倒过来放、`?cut=秒` 改切点、`?at=秒` 冻在整条拼接的某一帧（对帧用）。
**必须走 http**（B 是 ES module，`file://` 会被 CORS 拦），A 段本身的 md5 未变（`f50efb39…`）。
