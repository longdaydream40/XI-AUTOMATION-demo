## 二、这份 SVG 是怎么来的

### 1. 先把图拆成两种「墨」

原图是「白毛 + 淡灰晕染 + 一块实心红发夹」的半透明图。直接描边无法还原柔和明暗，所以先把每个像素按**白底合成色**拆成两种墨的覆盖率：

```
白底合成色 comp = 255·(1−g)·…  →  解 2 元最小二乘：
   255 − comp = 255·g·(1,1,1) + r·(255 − ink_red)
   g = 黑墨覆盖率   r = 红墨覆盖率   ink_red = #dd4b4f（从发夹实心区实测）
```

拟合残差：平均 0.027/255，最大 15/255，只有 0.03% 的像素超过 3/255。也就是说**这张图几乎完全可以用「黑墨 g + 红墨 r」两个标量场描述**。

### 2. 黑墨场按等距覆盖率分层

- 把 `g ∈ [0.004, 0.3498]` 等分成 **64 级**（每级间隔 0.0054），第 k 级取 `g ≥ T_k` 的区域。
- 每级区域用 **potrace 1.16** 矢量化（`-a 0.5`、`-t 8`）。
- 描摹前把 `g` 场**双线性放大 2 倍**再取阈值，把 potrace 的边界量化误差从 0.5 px 压到 0.25 px。
- 第 k 级在 SVG 里用「灰度 = 覆盖率」的实心路径写进 `<mask>`，再由一个黑色矩形取该 mask ⇒ 最终落地的黑墨覆盖率 = 第 k 级值。

> 为什么用 `<mask>` 而不是叠 64 层 `fill-opacity`：渲染器把每层 alpha 量化到 1/255，64 层半透明叠加会把误差累积成**系统性变亮**（实测平均 +2.5/255）。改用「不透明灰度 + 亮度 mask」后，每个像素只取一个值，量化误差不累积。

### 3. 红发夹单独处理（按你的要求：只要实心几何准，不要扩散色）

发夹取 `r` 场的 3 个实心等值线：**r ≥ 0.5 / 0.7 / 0.9**，直接输出实心红路径。
外围那圈 `r < 0.5` 的**扩散红晕被主动丢弃**——它属于「扩散色差」，不做成矢量。

### 4. 语义区块划分

用数据（红场最大连通块 = 发夹；被发丝围合的空白孔洞 = 可见侧脸）+ 几条沿发流走向的切分线，把画布**无重叠地**划成 9 块，加上浮在最上层的发夹，共 10 个语义区块。

## 三、校验结果

渲染用 `rsvg-convert`（cairo）与 Chromium 各出一份，两份互相差 MAE 0.20/255，说明**换渲染器结果一致，没有依赖某个引擎的私有行为**。

### 1. 实体线条 / 实心块几何（你要求的重点）

| 对象 | 量法 | 结果 |
|---|---|---|
| 红色发夹 4 根实心斜条边缘 | 用色度 `R−G`（对灰底免疫）求 50% 亚像素交叉点，48 个点 | **平均绝对偏移 0.163 px，最大 0.53 px** |
| 发型整体外轮廓（左缘） | 逐行 `ink = 0.05` 亚像素交叉，`y` 每 20 px 一次 | **−0.133 ± 0.247 px** |
| 发型整体外轮廓（右缘） | 同上 | **+0.018 ± 0.180 px** |
| 发丝暗线（`ink ≥ 0.12` 的线峰） | 扫描线找局部极大值并配对，2015 个点 | **平均绝对 0.229 px；86.7% ≤ 0.5 px，98.4% ≤ 1 px** |
| 发丝暗线（`ink ≥ 0.15`） | 816 个点 | **平均绝对 0.189 px；91.4% ≤ 0.5 px** |
| 发丝暗线保有率 | 源 `ink ≥ 0.08` 的像素 | **95.4% 在重绘里仍是 ≥ 0.08** |

结论：**实心块与线条的几何误差在 0.5 px 以内，属于亚像素级。**

### 2. 整体像素差（含扩散色差，作参考）

| 指标 | 值 |
|---|---|
| MAE | 0.611 / 255（0.24%） |
| RMSE | 2.31 / 255（0.91%） |
| PSNR | 40.87 dB |
| 99% 像素 | 差 ≤ 11 / 255 |
| 99.9% 像素 | 差 ≤ 24 / 255 |

剩下的大误差集中在「发夹边缘 1 px 环带 + 发丝极细暗线的峰顶 + 大面积的柔和晕染」——即第四节所说的扩散色差部分。

## 四、已知且**不打算**修的差异（按你的口径）

1. **发夹外围的扩散红晕**：源图里发夹外还有一圈很淡的红扩散，重绘中直接截断在 `r = 0.5`。
2. **大面积的柔和晕染层次**：黑墨按 64 级量化，理论上每级最多 0.7/255 的台阶；hue 上没有任何损失，但不会有源图那种连续的空气刷过渡。
3. **极细暗线的峰值**：宽度 1–2 px、峰值墨量落在两级之间的暗线，重绘后会暗一点点或亮一点点（峰值差平均 2.3/255，P99 16.5/255）。
4. **3 px 以下的孤立墨点**：被 `potrace -t 8` 当作噪点丢弃，对几何指标无影响（测试 TURD 0/2/4/8，线条保有率 89.0%→88.5%，发夹与轮廓偏移完全不变）。

## 五、语义区块表

根节点：`#wensi-head`，`data-semantic="head"`。每个区块是一个 `<g>`，带 `id` / `data-semantic` / `data-label`，内部含 `<title>`、`<desc>`。

| `id` | `data-semantic` | 中文 | 内容 |
|---|---|---|---|
| `face` | `face.profile` | 面部（可见侧脸） | 被头发围合、未被遮挡的侧脸区域；含额头、眉弓、鼻梁、鼻尖、人中、唇、下巴、下颌 |
| `haircrown` | `hair.crown` | 颅顶发 | 头顶主发流，自发旋向左右分股 |
| `hairbang` | `hair.bangs` | 刘海 | 覆于额前、自右上向左下散开的刘海束 |
| `hairback` | `hair.back` | 后脑发 | 后脑一侧的整块发量 |
| `hairsidelock` | `hair.sidelock` | 脸侧垂发 | 贴脸垂落的一束，遮住耳际；内侧边即面部轮廓线 |
| `hairtipsleft` | `hair.tips.left` | 左侧发尾 | 左下缘一排向外翘起的参差发尾（尖角发梢） |
| `hairtipsbottom` | `hair.tips.bottom` | 下缘发尾 | 底缘一排向下的尖角发尾 |
| `hairtail` | `hair.tail` | 长垂发 | 颈侧向下延伸、末端收细的一缕长发 |
| `hairrest` | `hair.misc` | 发块余部 | 未被细分规则命中的发丝余部 |
| `hairclip` | `accessory.hairclip` | 红色发夹 | 红色 K 形发夹：上下两道平行斜条 + 右侧一个「>」；**叠在头发之上**（唯一与其他区块空间重叠的区块） |

`<metadata id="wensi-regions">` 里有一份 JSON，字段：

```json
{
  "version": 1,
  "canvas": [1254, 1254],
  "compositing": "luminance-mask",
  "levels": { "gray": 64, "red": [0.5, 0.7, 0.9], "supersample": 2,
              "tracer": { "engine": "potrace 1.16", "alphamax": 0.5, "turdsize": 8 } },
  "ink_gray": "#000000",
  "ink_red": "#dd4b4f",
  "face_profile_guide": [[x, y], ...],
  "regions": [ { "id": 0, "box": "face", "label_zh": "…", "semantic": "…", "note": "…" }, ... ]
}
```

`face_profile_guide` 是从「可见侧脸」区块逐行取最右点得到的**面部轮廓引导线**（沿 y 每 16 px 取一个点，共 22 点，覆盖 y = 481…838），可以直接拿去驱动描边动画。

### 怎么在代码里用

```html
<!-- 内联进 HTML 才能被 JS 选中/改样式 -->
<g id="hairsidelock" data-semantic="hair.sidelock"> … </g>
```

```js
document.querySelectorAll('[data-semantic^="hair."]')  // 所有发块
document.getElementById('hairclip')                     // 发夹
```

- 每个区块的绘制是「一个矩形 + 一个 `<mask>`」；要改色就改那个 `rect` 的 `fill`，要整体隐藏就把 `<g>` 设 `display:none`。
- 想单独导出发夹：把 `#hairclip` 的 `<g>` 提出来即可，它自带 mask，不依赖别的区块。

## 六、复现方式

`build/` 目录里是完整的可复现脚本（Python + numpy + Pillow + potrace）：
`build3.py` → `assemble3.py` → `verify2.py` / `geomcheck.py` / `linecheck.py`，按顺序跑即可复现全部数字。

```bash
# 1) 拆墨 + 分区 + 分层描摹  → src/layers3.pkl
TURD=8 SCALE=2 N_GRAY=64 AMAX=0.5 python3 build3.py
# 2) 组装带语义标记的 SVG     → out/wensi-head.svg
SCALE=2 TURD=8 python3 assemble3.py
# 3) 像素校验（白底合成，与 rsvg 渲染逐像素比）
python3 verify2.py out/wensi-head.svg
# 4) 几何校验（发夹边缘 / 外轮廓 / 发丝暗线位置）
python3 geomcheck.py && python3 linecheck.py
```

依赖：`potrace 1.16`、`rsvg-convert 2.61`、Python 3 + numpy + Pillow。原始输入为 1254×1254 RGBA PNG。
