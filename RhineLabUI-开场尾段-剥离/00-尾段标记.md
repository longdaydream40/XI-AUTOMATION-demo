## 二、截图那一帧，画面其实还在动

先说准了：截图能确定的只有「三个点」，对应 **f457 – f478** 这 22 帧。这 22 帧里文案一个字都不变，**唯一在动的是 ∞ 标志轮廓上的那道缺口**：

```
f457  logo.start = 0.4030   logo.length = 0.9725
f470  logo.start = 0.6415   logo.length = 0.9725
f486  logo.start = 0.9640   logo.length = 0.9725   ← 停在这
```

`boot.ts` 是把它当虚线的偏移量写的：

```
this.contour.style.strokeDasharray  = `${s.logo.length} ${1 - s.logo.length}`;
this.contour.style.strokeDashoffset = String(-s.logo.start);
```

`pathLength` 被设成了 1，所以 `length = 0.9725` 意味着**轮廓上有 2.75% 是断开的**，`start` 在 0.4030 → 0.9640 之间把它绕着轮廓推。到 f486 停住，那里就是 `brand.ts` 注释里说的"印刷缺口"该在的位置。

换句话说：**你这张截图上的 ∞ 并不闭合，缺口在跑**。你以为标志早就画完了，其实它到 f486 才真正收口。

顺带把截图上的版式也对上了（这样你确认那确实是开场，不是我认错页）：

| 截图上的东西 | 代码里的出处 |

| 左上 `RHINE LAB / SYNTHESIZE INFORMATION / ANALYSIS OS` | `src/brand.ts:12` 的 `brandHeading`，`boot-motion.ts:69` 的 `brandTrack`（f278 起滑入，此时已落定） |

## 五、尾段生效 vs 依赖

片段文件里每段的标签就是分的这个。先说一个坑：

> **`bootMotion(t)` 是纯函数，它整个函数体从第一帧起每帧全跑。**
> 所以 `boot-motion.ts` 里没有哪一行是「只有尾段才执行」。标签里的「尾段生效」说的是：
> **这些行产生的可见效果落在窗口里**，前面几个阶段它们在空转（算出来的值写进 DOM 也是恒定值或 0）。

真正常条件执行的只有两处：

- `boot.ts:171` 的 `if (s.scanVisible) this.renderScan(s);` —— `renderScan`（197–264）只在 f487–f568 真被调用；
- `boot-motion.ts` 里的几个 `if (f >= …)` / `at(f, […])` 分支，比如第 44–46 行的点和缺字。

- `boot.ts:133-137 / 141-158 / 161-169` —— access、字形节点、加减号、brand 三行、powered，尾段里全部恒定但**每帧仍在写**

## 八、想从这一帧起播，改一个常量就够

时间轴是纯函数（`bootMotion(t)` 无状态），所以「从这一帧开始播」不需要改任何动画代码 —— 只要把起点从 1.76 挪到 13.28。

`main.ts:1548-1550`：

```ts
bootStart =
  performance.now() / 1000 -
  (reviewParams.has("time") ? Number(reviewParams.get("time")) : 1.76);
                                                                  ↑ 改成 13.28
```

`main.ts:644` 的 `replayBootAfterModal` 里还有一份同样的 `1.76`，重播时也要改。

**别用上游自带的 `?time=13.28`。** 那条路会把 `reference` 打开（`main.ts:407-408`），版式从 `openingLayout` 换成 `viewportLayout`（`main.ts:409-417`），手机上的取景会和你截图那张不一样。要只冻结画面看那一帧，`?time=13.28&freeze=1` 仍然是最方便的（`main.ts:138-140`）。

一个坑：`restartBoot()` 把音频时间轴钉死在 6.76（`audio.ts:390`）。只跳画面不改它的话，音乐会从开头放，和画面差 11.5 秒。
