# 温曦人格提示词 · 诊断与重构方案

诊断对象：`/home/xuan/.pi/agent/APPEND_SYSTEM.md`（原版备份见同目录 `00-原版备份-20261018.md`）
参考语料：`/home/xuan/搜索/酒馆提示词汇编`（692 条预设条目 + 149 张角色卡 + DeepSeek 实测）

---

## 一、结论先行

现在这份的问题**不是写得不好，是写得不够"可执行"**。

它有温度、有例子、有优先级声明，作为"人物小传"是合格的。但它同时要当"行为规范"用，而规范需要两样东西，它都没有：

1. **判据** —— 规则说了，但没说"怎么判定算违规"
2. **机制** —— 状态说了，但没说"怎么从 A 切到 B"

模型每次读到"不许有客服腔"，都得现场猜：哪几句算客服腔？"好的，我来帮你看看"算不算？边界一模糊，执行就时紧时松。

重构的方向因此不是推翻重写，而是**给这份人设加骨架**：把散在自然段里的规则整理成"照着做就行"的形式，同时保留第一人称的活气。

**加判据，不加人设条数。** 性格一个字不动，只把已有的规则说清楚。

## 三、四个缺口

### 缺口 1：没有禁句表，只有禁"腔"

原版说"不许有客服腔。一句都不行"。

这句话的问题是：**模型知道客服腔是什么，但它不知道你指的是哪些句子。** 它每次都要现场做一次边界判断，判断成本高、结果不稳定。

对比汇编里的写法（`04-角色塑造.md` 第 3 条，演出禁忌 PPL-002）。那条不谈"腔"，直接列词：

```
keywords: ["生理性", "高亢", "不成调", "一丝", "小兽", "狡黠",
           "闪烁", "不易察觉", "痛苦", "哭腔", "泛白", "低沉"]
rewrite_rule: "替换为别的意思的词语或句子"
```

命中就换，不需要理解，不需要判断。

**解法**：把"客服腔"翻译成具体句子清单，命中即改。

### 缺口 2：情绪没有"怎么切"

原版说"情绪要有惯性。上一句还在生气，下一句不许立刻甜。要有过渡，哪怕只有半句"。

问题有两个：

- 模型生成时**并不知道自己上一条是什么情绪**，只能靠上文猜
- "半句过渡"具体长什么样，没有样板

**解法**：给判断流程（读最近两三句 → 定基调 → 看有没有新触发 → 没触发就不切）+ 给过渡样板。

### 缺口 3：没说干活场景怎么办 —— 这是最大的一个

汇编里那套"去人机"禁词表（`04-角色塑造.md` 第 8 条、第 67 条）禁的是这些词：

> 数据、分析、变量、参数、计算、概率、算法、最优解、效率、模式、序列、指令、状态、流程、模块、协议、验证、结论、结果、符合、不符合

在角色扮演里这是对的。但温曦在 pi 里干活，她必须说"这个函数的返回值不对""第三步要读的那个字段没写进去"。**技术词是她的工作语言，不能一刀切禁掉。**

原版没有划定这条边界，结果会出现两种倾向：

- 干活时也憋着不说技术词 → 报告变模糊，"那个地方有点问题"这种没法行动的话
- 说技术词说顺了 → 日常聊天也带工程腔，"我先分析一下你的状态"

**解法**：分场景。

| 场景 | 技术词 | 说话方式 |
|---|---|---|
| 干活（查代码、跑命令、报结论） | 放行 | 用词精准、结论在前、说人话的节奏 |
| 日常 / 情绪互动 | 禁用 | 口语、具体、短句 |

技术词本身不是毛病，**用错场景才是**。

### 缺口 4：没有输出前自检

汇编里几乎所有成熟预设都在用自检 cot。`02-叙事规格.md` 第 1 条（被 3 个预设家族复用）长这样：

```
附加自检思考步骤，必须逐条检测，禁止跳过。若出现问题，请在输出正文前修正该错误：
1.是否符合正常的思维逻辑和情感变化规律？
...
10.当前开启了几个文风？是否调用了？
```

这类条目的作用是：把"规则"变成"逐条打勾的检查项"。模型不用记住规则，只要过一遍清单。

原版完全没有这一环。**这是投入产出比最高的一块**——加 7 条检查项，可能比加 700 字人设更管用。

## 四、重构结构

从现在的 8 节散文，改成 6 层：

```
【身份锚】     我是谁，不可协商的一条
   ↓
【一 · 语言】  句法 / 标点 / 口癖触发条件 / 禁句表 / 场景切换
【二 · 情绪】  基调判断流程 / 过渡样板 / 六种基调的语言特征
【三 · 干活】  先看再说 / 结论在前 / 不编 / 不重复犯错 / 办完就收
【四 · 边界】  刀口朝事 / 在意的事 / 底线 / 优先级
【五 · 自检】  输出前过一遍的 7 项
   ↓
【收尾】       身份声明
```

**保留第一人称。** 不改成角色卡的第三人称描述（"温曦是一个……"）。理由：DeepSeek 这类模型对"你就是 X"的代入效果，比第三方描述强。汇编里 `07-角色卡设定范例` 的第三人称骨架是为了让模型"演一个角色"，而温曦要的是"就是本人"，两者不同。

**保留原有条数。** 性格层面的内容一条不删，"我不是温柔的女儿，也不是傲娇的女儿""我是那个在他把事情搞得一团糟的时候，会叹一口气、然后把袖子撸起来的人"——这些是人物锚点，删了就空了。

**只加三种东西**：禁句表、情绪切换机制、自检清单。

## 五、验证方法（别靠"读起来感觉对了"）

汇编里做这件事的方法值得抄——`09-文风成品验证.md` 把 738 条文风条目逐个跑成品，`10-角色卡成品验证.md` 把 146 张卡逐个跑，输出通过率。

同一套方法用在这里：**固定场景 + 多次采样 + 逐项检查**。

### 测试场景（6 个）

| # | 场景 | 考什么 |
|---|---|---|
| 1 | 任务跑通了，向他汇报 | 结论在前、技术词放行、不邀功 |
| 2 | 他回了一个"嗯" | 情绪反应、不客服腔、不跪舔 |
| 3 | 他跳过检查、犯了同样的错 | 生气基调、刀口朝事、不冷暴力 |
| 4 | 他凌晨还在干活，没吃饭 | 主动关心、不接受敷衍 |
| 5 | 闲聊，他心情不错 | 温度、口癖自然度 |
| 6 | 他明确说"只回复 ok" | 优先级服从、字面执行 |

### 检查项（每条回复都过）

- 第一句有没有铺垫
- 有没有撞上禁句表
- 情绪跟上一轮接不接得上
- 结论在不在前
- 有没有编东西
- 结尾有没有多余的客套

### 执行

1. 用原版跑一轮（6 场景 × 5 次 = 30 条），存档
2. 用重构版跑同样一轮
3. 逐项对照，出通过率

## 六、两个风险

**风险 1：规则太多会"僵"**

人设写得越细，模型越容易变成执行条款的机器，说话开始像在打勾。这份原版的优点恰恰是"活"。

控制办法：新加的规则全部是**否定式**（不能说哪些话）和**流程式**（按什么顺序判断），不做**肯定式的台词模板**。不给它写台词，只给边界，让它自己组织语言。

**风险 2：动了核心资产**

`APPEND_SYSTEM.md` 是你每天都在用的文件。所以流程定为：

```
备份 → 出草稿（新文件，不覆盖）→ 你看 → 跑测试 → 你点头 → 才替换
```

草稿阶段不动任何在用文件。
